# Webレスポンシブ表示調整 設計

作成日: 2026-08-30  
対象: `vishu-renewal-web`

## 1. 目的

端末の画面幅・高さが変わっても、写真の主題、コンテンツの優先順位、操作性が変わらない表示にする。

ここでいう「同じ見え方」は、全端末で写真の同じピクセル範囲を表示することではない。縦長端末と横長端末でそれを強制すると、余白が生じるか写真が過度に小さくなるため、次の状態を達成条件とする。

- 写真内の人物、髪、設備、入口などの主題が常に見える
- 画像が引き伸ばされず、端末ごとに意図しない切り抜きへ変わらない
- 見出し、説明、主要ボタンの順序と強弱が変わらない
- コンテンツが画面外へはみ出さず、意図しない横スクロールが発生しない
- ブレークポイントの前後で画像の縦横比や表示位置が急に変わらない

## 2. 対象範囲

公開・顧客・管理画面にある次の表示を対象とする。

1. トップページ
   - 店内のヒーロー画像
   - 髪質改善・縮毛矯正のBefore／After画像
   - シャンプー台画像
   - 玄関画像とGoogle Maps
   - ヘッダー、各セクション、固定予約ナビゲーション
2. 顧客画面
   - ログイン／パスワード再設定の背景画像
   - 予約メニュー画像
   - マイページ、予約フォームのカードと入力欄
3. 管理画面
   - メニュー一覧のサムネイル
   - メニュー画像編集のプレビュー
   - 管理ナビゲーションとフォーム

Google Mapsのiframe内部、OSやブラウザ固有の入力UI、アップロードされた元画像自体の品質は対象外とする。

## 3. 現状と課題

| 箇所 | 現状 | 課題 |
| --- | --- | --- |
| 店内ヒーロー | PCは可変高、スマホは `1179 / 1563`。`object-position` が `42%`、`38%`、中央へ切り替わる | 画面幅の境界で写る範囲が急に変わる |
| Before／After | PCは `4 / 3`、スマホは `4 / 5`。元画像はほぼ `3 / 4` | PCで縦長の髪写真が大きく切れ、端末で比較対象が変わる |
| シャンプー台 | 元画像、表示枠ともに `16 / 9` | 基本方針は適切。枠幅と余白だけ統一対象 |
| 玄関 | 縦長の元画像を、高さ固定の横長枠へ `cover` で表示 | 端末幅により入口の見える範囲が変わる |
| 予約メニュー画像 | PCは正方形、スマホは `52 x 60` | 画像比率が端末で変わる |
| 管理メニュー画像 | 一覧は固定幅・固定高、編集は `4 / 3` | 一覧と編集プレビューの表示契約が明文化されていない |
| レスポンシブ規則 | `680`、`760`、`767`、`820`、`840` などが混在 | 同じ要素へ複数ルールが重なり、境界付近の予測が難しい |

## 4. 基本方針

### 4.1 画像表示契約

画像ごとに次の4項目を決め、ブレークポイントでは変更しない。

1. 表示枠の縦横比
2. `object-fit` または `background-size`
3. 焦点位置
4. `next/image` の `sizes`

画像の役割に応じて表示方法を分ける。

- 雰囲気を伝える写真: 枠を満たす `cover` を使用し、焦点位置を固定する
- 施術結果の比較写真: 写真全体の比較を優先し、元画像に合わせた縦横比を固定する
- メニューのサムネイル: 同じ大きさで一覧性を優先し、正方形または `4 / 3` に固定する
- ロゴや図など全体を見せる素材: `contain` を使用する

焦点位置はCSSへ散在させず、画像枠のカスタムプロパティ `--image-position` に集約する。将来画像を差し替える場合も、この値を素材ごとに調整する。

### 4.2 レイアウト

- ページ左右余白は `clamp(18px, 4vw, 32px)` を基本とする
- 本文領域は既存デザインに合わせ、最大幅 `1180px` または `1240px` を維持する
- Gridは `minmax(0, 1fr)` を使用し、長文や画像が列幅を押し広げないようにする
- モバイルで固定の `min-height` を使わず、内容量または `aspect-ratio` で高さを決める
- 文字サイズは本文の可読性を損なわない範囲で `clamp()` を使用する
- ボタンと入力欄は全端末で44px以上の操作領域を確保する
- 予約時間表のように横幅が必要なUIだけ、ラベル付きの横スクロールを許可する
- 下部固定ナビゲーションは `safe-area-inset-*` を含め、本文と重ならない余白を確保する

### 4.3 ブレークポイント

画面全体では次の3区分を基準とする。

| 区分 | 幅 | 基本レイアウト |
| --- | ---: | --- |
| Mobile | `0–767px` | 1カラム、下部予約ナビゲーション |
| Tablet | `768–1099px` | 1カラムまたは内容に応じた2カラム |
| Desktop | `1100px以上` | 2カラム、最大幅コンテナ |

コンポーネント固有の折り返し点は許可するが、画像の比率・焦点位置を変える用途には使用しない。既存の `680px` 以下のルールは小型端末向けの余白・文字・操作領域調整に限定する。

## 5. 画像ごとの確定仕様

| 画像 | 表示枠 | 表示方法 | 焦点・補足 |
| --- | --- | --- | --- |
| 店内ヒーロー | Desktopはヒーロー高に追従、Mobile／Tabletは `3 / 4` | `cover` | 全区分 `center 42%`。シェードと見出しの可読性も同じ基準にする |
| Before／After | 全区分 `3 / 4` | `cover` | `center`。BeforeとAfterは同じ寸法・位置にする |
| シャンプー台 | 全区分 `16 / 9` | `cover` | `center`。既存仕様を維持する |
| 玄関 | 全区分 `4 / 3` | `cover` | `center 42%`。入口が欠ける場合だけ焦点値を素材単位で調整する |
| ログイン背景 | パネル全面 | `background-size: cover` | ログインは `42% center`、再設定は `center 42%` を素材固有値として固定する |
| 予約メニュー | 全区分 `1 / 1` | `cover` | 画像枠は幅だけ変更し、高さは `aspect-ratio` から算出する |
| 管理一覧 | 全区分 `4 / 3` | `cover` | 一覧の幅だけレスポンシブにする |
| 管理編集プレビュー | 全区分 `4 / 3` | `cover` | 一覧と同じ切り抜きを確認できるようにする |

店内ヒーローだけはDesktopの左右2カラム構成を維持するため表示枠比率が異なる。ただし焦点位置を固定し、主題が欠けないことを受入画像で確認する。1枚の元画像で主題を維持できない場合は、CSSで無理に補正せず、同じ元写真からDesktop用とMobile用のトリミング画像を作る。

## 6. コンポーネント別設計

### 6.1 トップページ

- HeroはMobileへの切り替え時も画像、見出し、説明、CTA、基本情報の順序を固定する
- Before／Afterは小型端末でも2枚を横並びにし、比較できることを優先する
- Before／Afterの間隔は可変にするが、画像比率は変えない
- シャンプー台はDesktopで画像と説明を2カラム、Tablet以下で画像、説明の順に1カラムとする
- 玄関と地図はDesktopで2カラム、Tablet以下で玄関、地図の順に1カラムとする
- 玄関と地図の高さを固定値で揃えず、それぞれの `aspect-ratio` で確保する
- 主要CTAはMobileで横幅100%、Desktopでは内容幅とする

### 6.2 顧客画面

- ログイン系の写真パネルはDesktopで左カラム、Tablet以下でフォーム上部へ配置する
- 写真パネルの高さは画面高の固定値ではなく `clamp()` で上限・下限を設ける
- 予約メニュー画像は正方形を維持し、Mobileでは52px、Tablet以上では76pxを基準幅とする
- 予約ステップ、カード、入力欄は1カラム化してもDOM順を変えず、キーボードのフォーカス順を維持する
- 予約時間表の横スクロール領域はページ全体へ波及させない

### 6.3 管理画面

- 760px以下では既存どおりナビゲーションを下部へ移す
- 一覧、フォーム、ダイアログはページ全体を横スクロールさせない
- メニュー画像は一覧と編集プレビューをともに `4 / 3` にし、保存後の見え方を編集時に確認できるようにする
- 画像以外の表はMobileでカード表示または情報の縦積みにし、主要操作を省略しない

## 7. 実装方針

主な変更対象は次のとおり。

- `src/components/home/home-page.module.css`
- `src/components/home/home-page.tsx`
- `src/app/globals.css`
- `src/features/booking/components/booking-flow.tsx`
- `src/features/auth/components/customer-login.tsx`
- `src/features/auth/components/customer-password-reset.tsx`
- `src/features/admin/components/admin-console.tsx`

実装順:

1. 共通の余白、コンテナ、画像枠の規則をCSS変数として整理する
2. トップページ4種類の写真比率と焦点位置を修正する
3. ログイン背景、予約メニュー、管理メニュー画像を修正する
4. 重複するメディアクエリを整理し、レイアウト用途と小型端末用途を分ける
5. 全対象幅で表示確認し、`sizes` を実表示幅に合わせる

API、Firestore、認証、予約ロジックの変更は行わない。

### 8.1 基準ビューポート

### 8.2 受入基準

- 全基準ビューポートで、意図しないページ全体の横スクロールがない
- 写真の主題がすべて見え、縦横に引き伸ばされていない
- Before／After、予約メニュー、管理メニュー画像の比率が端末間で変わらない
- ブレークポイントの1px前後で、画像の焦点や比率が急変しない
- 見出し、本文、ボタンが画像や固定ナビゲーションに重ならない
- 200%ズームでも主要操作と入力項目を利用できる
- 画像領域が読込前から確保され、目視できるレイアウトシフトがない
- `next/image` の候補幅が実表示幅に対して過大・過小になっていない
- `npm run lint`、`npm test`、`npm run build:dev` が成功する

実装前後で同じビューポートのスクリーンショットを保存し、特にヒーロー、Before／After、玄関、予約メニューを並べて比較する。可能であればPlaywrightのスクリーンショットテストを追加し、以後の画像比率とレイアウトの退行を検出する。
