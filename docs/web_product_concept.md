# Salon Vishu Webサービス構想

## 目的

Salon Vishuのホームページ、Web予約、店主管理をひとつのサービスとして提供する。お客様には予約まで迷わない体験を、店主には日々の運用が一か所で完結する体験を作る。

## 想定ユーザー

### お客様

- サロンの雰囲気、メニュー、価格、アクセスを知りたい
- 電話や外部予約サイトを経由せず、空き時間を確認して予約したい
- 予約内容の確認、変更、キャンセルをしたい

### 店主・スタッフ

- 予約を日・週単位で確認したい
- 予約の追加、変更、キャンセル、来店完了を管理したい
- メニュー、料金、所要時間、営業時間、休憩・予約不可時間を変更したい
- 将来的に顧客履歴、カルテ、売上を確認したい

## MVPの範囲

### 公開サイト

- トップ、コンセプト、メニュー、アクセス、営業時間
- SEO、SNS共有、スマートフォン対応
- 予約ページへの明確な導線

### Web予約

- メニュー選択
- 空き日時選択
- お客様情報・要望入力
- 予約内容確認と確定
- 完了通知（メールを優先）

### 店主管理

- 店主ログイン
- 予約一覧・詳細・ステータス変更
- メニュー管理
- 営業時間、定休日、予約枠間隔、予約不可時間の管理

## MVPの対象外

- オンライン決済、POS、会計連携
- 複数店舗・フランチャイズ対応
- 複雑な指名・歩合・シフト計算
- 本格的な電子カルテ
- 旧データの自動移行

対象外の機能もデータモデルを壊さず後から追加できるようにするが、初回リリースには含めない。

## 基本方針

- お客様はアカウント作成を強制しない。MVPはFirebase Anonymous Authを内部的に利用し、連絡先で予約できる方式を推奨する。
- 店主はFirebase Authのメール・パスワード認証を利用し、`adminUsers/{uid}` の `uid` フィールド一致で権限を確認する。
- 日時はFirestore Timestampで保存し、表示・営業時間判定は `Asia/Tokyo` とする。
- 空き枠表示は参考情報、予約確定時のサーバー側トランザクションを最終判定とする。
- 旧 `salon_vishu` の本番データを直接変更せず、開発プロジェクトで検証してから移行方針を決める。

## 成功指標の例

- トップページから予約完了までの到達率
- 予約開始から完了までの離脱率
- 電話・DMでの予約調整件数の減少
- 店主が予約確認・変更に使う時間
- 二重予約と予約内容不整合の発生件数（目標0件）

## 合意が必要な項目

- 実際の店舗住所、電話番号、営業時間、定休日
- 掲載するメニューと価格表記
- 予約受付期限、変更・キャンセル期限
- お客様のログインを必須にするか
- スタッフ指名をMVPに含めるか
- 予約通知先メールと通知方法
- 旧アプリとWebを同じFirebaseデータに統合する時期
